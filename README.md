# Diabetes-Predictor-Project
Predicting diabetes in people based on data in a given dataset


For my project, I chose to look into predicting diabetes based on various health factors in individuals. I decided to do a project on this topic because I care deeply about my health and found it rather interesting. Also, the implications of such a project matter, since diabetes is a growing issue, especially among youth, so finding effective ways to predict it is important. The data I used for this project contains different factors that measure the health of various individuals with and without diabetes. Factors considered include sex, age, BMI, physical health, mental health, and so on. This project aimed to use these factors as predictors for determining if someone has diabetes or not. The research paper and data set referenced while working on this project are attached below in the sources section. 
The code for my project starts off by running a lot of preprocessing. I first checked for missing values in each factor to ensure that nothing would mess with the algorithm later. After that, I removed duplicate rows from the data set. I then scaled the cleaned-up data for easy visualization. I chose to only scale variables that weren't binary, but this decision likely had little impact on my results, and I probably could have scaled all variables. I used the processed data in my exploratory data analysis. Since all the data was categorical, I figured that one of the only useful visualizations would be boxplots. The boxplots helped show how the different factors correlated with diabetes expression. For most of the factors, it didn’t appear that they had a significant correlation with diabetes in individuals. A few factors like age and BMI showed stronger correlations with diabetes, but still not the most significant. Initially, when working on this project, I considered grouping the data via a hyperplane, and even attempted to graph the data in a 3d space to visualize it during my exploratory data analysis. However, since the data was categorical and 3d plots seemed not to be the most useful, I came to the conclusion that some form of decision tree would be the best option. The code for this was removed to prevent the final project from being too confusing.
After deciding that I was going to use some form of decision tree for my project, I started actually creating the models. I felt that a random forest model would be the best model for this since it is a variant of a decision tree and is also an ensemble method, making it generally more robust than standard models due to having a voting process. The examples of random forest shown in class made it seem like an optimal method over alternative options like Ada Boosting and a standard decision tree. But, to verify this, I also made a separate model, which was a standard decision tree. I started by splitting the data into a training and testing set, with 80 percent in the training set and 20 percent in the testing set. Additionally, I stratified by whether the individuals had diabetes to ensure that the training and test data had an even ratio of people with diabetes to people without it. I then constructed the models and used grid search to find the optimal parameters for the decision tree.
I think the biggest thing that surprised me while working on this project, though, was that the optimized decision tree outperformed the random forest model. The random forest model had an accuracy of 0.6970, a precision score of 0.6977, a recall score of 0.7400, and a F1-score of 0.7182. The individual trees in the random forest model had similar metrics, all with an accuracy of around 0.63. The decision tree that was optimized using grid search, on the other hand, had an accuracy of 0.7264, a precision score of 0.7299, a recall score of 0.7549, and a F1-score of 0.7422. Regardless of the metric, the regular decision tree performed better than the random forest model. I tried going beyond what was taught in the course and attempted to change the parameters for the random forest model, but that didn’t help it. I tried doing this through hyperparameter tuning; however, I ran into an issue of it taking a lot of time and processing power, since Google Colab struggled to do it, so I eventually gave up on trying that. Because of this, I decided to use the optimized decision tree as my final model. I added an additional, more interactive section showing off the different metrics of my final model, as well as the map of the decision tree, and a spot where someone can put in their information to see what the model predicts for them.
I feel that working on this project gave me the chance to sort of experiment on my own and come up with my own solutions to a problem. With previous projects and assignments in class, it felt like what I had to do to complete a problem was sort of laid out for me in the instructions. With this project, since it was more open, I didn’t have everything laid out. I feel that because of this, I learned more about how to go about conducting a data science research project on my own. I personally also felt that my project was able to somewhat answer the problem I sought out to solve and, on top of that, had some interesting conclusions. My model was able to somewhat predict if someone has diabetes or not based on various health and demographic factors, as I sought out to do. The data also revealed that BMI, age, physical health, and general health were the most useful features for predicting if someone had diabetes. Overall, though, I think the key takeaway from this project was the experience of doing my own mini project, and the fact that different demographic features can somewhat reliably be used to predict if someone has diabetes is a plus.
